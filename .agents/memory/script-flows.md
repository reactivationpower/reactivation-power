---
name: Script flow content-as-code
description: Constraints and quirks when rewriting or applying reactivation call scripts (content/flows JSON, lint, apply, player rendering).
---

- Player italicizes a coaching note only when the whole paragraph is wrapped in parentheses; a note glued onto a spoken line renders as speech.
- Choice identity in the DB is not unique on (from_step_key, to_step_key); apply pairs duplicates by sort_order. Keep sort_order stable when rewording labels.
- Lint counts two "?" in one breath (no period between) as one error, so multi-option questions must be stated as a sentence ("I usually hear one of three things. A, B, or C. Which is closest?").
- Lint R2 counts a `{{token}}` as one word and splits sentences only after `.!?` followed by a capital; comma-joined clauses read as one sentence, so split with a period rather than trimming words.
- Lint R10 chip matching: chip label words are stemmed and stopworded (back/coming/routine dropped, so the "Back" chip matches the literal word "back" — keep "back" out of other questions); "Which area(s)…" lines are excluded from the question count, so open a question with "Where…" instead.
- Dental parent-mode flows: the `{{pt_*_q}}` stacked-question tokens render multi-question text that fails the guide; write plain questions with only the short pronoun tokens (pt_you / pt_your / pt_them / pt_your_file / pt_get_you_in / pt_no_fault). Avoid verb agreement after `{{pt_you}}` ("your child notice"); phrase as "Does it come up…". Start `{{pt_no_fault}}` after "and", never as a sentence opener (it is lowercase). In parent mode, avoid unattributed feeling phrases ("or feeling confident?") on shared screens; attach the pronoun token ("or {{pt_your}} confidence?") so the line reads about the child, not the parent. Only clear-aligners and orthodontics-braces carry parent mode.
- Demo account has niche_access for the chiro-family niches (Chiropractic, Decompression, Joint Pain, Neuropathy, ChiroThin, Gut Health, Red Light) plus Acupuncture, Massage Therapy and Acoustic Wave Therapy (one showcase patient each, stamped 08:03–08:05 ET so they land in the first cold-call batch); to click-test another niche insert a temporary niche_access row for the demo owner (dr.whitaker@demo.reactivationpower.com) and delete it afterwards. The demo owner may already carry temp rows from other batches; only delete the rows you inserted.
- The player filters niches by the owner's sector, derived from course_access. To click-test a home_services niche as the demo owner you must also grant the Home Services course temporarily (plus the niche_access row), then delete both. The demo seeder re-upserts its own niche_access set on rebuild, so counts change on their own.
- Player click-through route is `/portal/dialer/script` (not `/portal/script`); demo login is `/demo` with the DEMO_PASSWORD secret. The testing subagent times out on exhaustive branch traversal; give it one niche and a few branches per round, and rely on the programmatic routing-identity check (git HEAD vs JSON) for the rest.
- New niche = new JSON file + `flows:apply --create-niches <slug>` (inserts the niche row from the file's niche block by name; never edits an existing row) + chips in BOTH concern-options.ts copies (api-server and reactivation-power) + service-catalog/niche-match in both copies + NICHE_SAMPLES in templates.ts.
- Facial-aesthetics niches (Fillers, IPL, Microneedling, Laser Resurfacing, Acne, Pigmentation, Rosacea, Peels, Facials, Skincare) use Fillers as the reference; four niche objections at 100-103, lapsed_wait (not lapsed_wait_pain), obj_think/obj_send_info wired to scheduling/uncover. Keyword rules for them sit before Skin Tightening so "microneedling"/"morpheus" resolve to the Microneedling niche.
- Home-services niches had no concern chips at all; chips were added in the same order as the digging_in focus buttons so the tapped chip fills {{main_concern}} on the recommendation screen.
- Pre-existing dead ends: obj_think / obj_send_info have no outgoing choices in the older niches (Skin Tightening, med spa, dental); the facial-aesthetics niches wire them. (Chiropractic/decompression obj_came_back_stopped/obj_managing_own and all four Acoustic Wave niche objections were wired to scheduling/uncover in Sept 2026.) Red Light / Cellulite lapsed_commitment has one button straight to scheduling (no lapsed_* screens). (hvac/plumbing's unfilled {{asked_by}}/{{practice_phone}} tokens were fixed in the home-services rewrite.)
- Routing additions (new choices) are fine when the task is explicitly a routing task: add the choice object to the JSON with the next sort_order and flows:apply inserts it; re-export afterwards to confirm the JSON round-trips. If a screen's coaching note names the URGENT button, that screen must have its own `urgent` choice.
- Making It Real screens share one scaled three-question shape (see style guide example 5). The owner's reference impact line ("...interfere with things like work, at home, or relaxing...") is 22 words and fails lint R2; the applied version drops "things like" (20 words). Keep every question ≤20 words with a single "?" — lint splits R1 units only on `.!`, so a question cannot be split in two.
- The facial-aesthetics JSONs were hand-written with compact one-line choices; any export (or JSON.stringify re-save) expands them, so a small text edit shows a ~800-line diff. Verify text-only changes by parsing HEAD vs working tree (choices/step meta identical), not by diff size.
- Task agents share the same Supabase flow tables, so an unmerged task's `flows:apply` can leave the DB ahead of main's JSON. Before `flows:apply --all`, read the dry-run and, for any step you did not touch that shows as an update, export that slug and adopt the DB text into the file rather than reverting it.
- Every flow routes Making It Real → `review` (general's review when the niche has none) → `recommendation`. The owner-approved read-back ("let me make sure I have this right… Did I get that right?") lives on `review`; `recommendation` opens with the bridge ("that's worth getting looked at instead of just dealing with it. Can I make a recommendation?"). Never put the read-back on both or the caller says it twice. The owner picked this split explicitly (Sept 2026). Two caveats: a niche with no `review` of its own inherits general's (work/home/own-time buckets), so any niche whose Making It Real buckets differ needs its own `review` override; and general's `doing_well_variant` "no signs" button goes straight to `recommendation`, so general's bridge must not presume an active problem (only matters when no niche is selected — the picker has no general option).
- `flows:export` after apply also pulls in choice rows another unmerged task inserted (e.g. objection → scheduling buttons). For a text-only task, restore `choices` from git HEAD for those files instead of committing the other task's routing.
- The player fetches the whole flow once per page load; after `flows:apply`, a click-tester must hard-reload before it sees new rows.
- Owner-approved rule: `{{provider_name}}` is always spoken as "Dr. <last name>" (never first name, never the business name — that sounds like a call centre); when no doctor applies it becomes "the whole office", so write the token mid-sentence in a shape that reads with either value.
- The API Server workflow is often stopped between sessions; a demo sign-in "Request failed (502)" in the player means restart it, not an app bug.

**Why:** Text rewrites must never alter routing (no DDL, routing owned by the product); the tooling only updates text in place.
**How to apply:** Any script rewrite: export → edit JSON → flows:lint → flows:apply --dry-run → apply → click through in the player with the niche enabled for the demo owner.
