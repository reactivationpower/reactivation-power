---
name: Script flow content-as-code
description: Constraints and quirks when rewriting or applying reactivation call scripts (content/flows JSON, lint, apply, player rendering).
---

- Player italicizes a coaching note only when the whole paragraph is wrapped in parentheses; a note glued onto a spoken line renders as speech.
- Choice identity in the DB is not unique on (from_step_key, to_step_key); apply pairs duplicates by sort_order. Keep sort_order stable when rewording labels.
- Lint counts two "?" in one breath (no period between) as one error, so multi-option questions must be stated as a sentence ("I usually hear one of three things. A, B, or C. Which is closest?").
- Lint R2 counts a `{{token}}` as one word and splits sentences only after `.!?` followed by a capital; comma-joined clauses read as one sentence, so split with a period rather than trimming words.
- Lint R10 chip matching: chip label words are stemmed and stopworded (back/coming/routine dropped, so the "Back" chip matches the literal word "back" — keep "back" out of other questions); "Which area(s)…" lines are excluded from the question count, so open a question with "Where…" instead.
- Dental parent-mode flows: the `{{pt_*_q}}` stacked-question tokens render multi-question text that fails the guide; write plain questions with only the short pronoun tokens (pt_you / pt_your / pt_them / pt_your_file / pt_get_you_in / pt_no_fault). Avoid verb agreement after `{{pt_you}}` ("your child notice"); phrase as "Does it come up…". Start `{{pt_no_fault}}` after "and", never as a sentence opener (it is lowercase). In parent mode, avoid unattributed feeling phrases ("or feeling confident?") on shared screens; attach the pronoun token ("or {{pt_your}} confidence?") so the line reads about the child, not the parent. Only clear-aligners and orthodontics-braces carry parent mode.
- Demo account has niche_access for the chiro-family niches (Chiropractic, Decompression, Joint Pain, Neuropathy, ChiroThin, Gut Health, Red Light) plus Acupuncture, Massage Therapy, Acoustic Wave Therapy, Weight Loss (Not ChiroThin), GLP Patients and Cellulite Reduction (one showcase patient each, stamped 08:00–08:08 ET; demo batch size is 10 so all land in the first cold-call batch — the showcase list must stay <= the batch size, and the largest allowed batch size is 10, so the next demo niches beyond 10 showcases need a different mechanism, e.g. rotating showcases or a second batch); to click-test another niche insert a temporary niche_access row for the demo owner (dr.whitaker@demo.reactivationpower.com) and delete it afterwards. The demo owner may already carry temp rows from other batches; only delete the rows you inserted. Both demo config copies (api-server and reactivation-power) must be kept identical; the web copy had drifted once.
- The player filters niches by the owner's sector, derived from course_access. To click-test a home_services niche as the demo owner you must also grant the Home Services course temporarily (plus the niche_access row), then delete both. The demo seeder re-upserts its own niche_access set on rebuild, so counts change on their own.
- Player click-through route is `/portal/dialer/script` (not `/portal/script`); demo login is `/demo` with the DEMO_PASSWORD secret. The testing subagent times out on exhaustive branch traversal; give it one niche and a few branches per round, and rely on the programmatic routing-identity check (git HEAD vs JSON) for the rest.
- New niche = new JSON file + `flows:apply --create-niches <slug>` (inserts the niche row from the file's niche block by name; never edits an existing row) + chips in BOTH concern-options.ts copies (api-server and reactivation-power) + service-catalog/niche-match in both copies + NICHE_SAMPLES in templates.ts.
- Facial-aesthetics niches (Fillers, IPL, Microneedling, Laser Resurfacing, Acne, Pigmentation, Rosacea, Peels, Facials, Skincare) use Fillers as the reference; four niche objections at 100-103, lapsed_wait (not lapsed_wait_pain), obj_think/obj_send_info wired to scheduling/uncover. Keyword rules for them sit before Skin Tightening so "microneedling"/"morpheus" resolve to the Microneedling niche.
- Home-services niches had no concern chips at all; chips were added in the same order as the digging_in focus buttons so the tapped chip fills {{main_concern}} on the recommendation screen.
- Pre-existing dead ends: obj_think / obj_send_info have no outgoing choices in the older niches (Skin Tightening, med spa, dental); the facial-aesthetics niches wire them. (Chiropractic/decompression obj_came_back_stopped/obj_managing_own and all four Acoustic Wave niche objections were wired to scheduling/uncover in Sept 2026.) When a routing task replaces a single button with a branch, the old row cannot be deleted by the tooling, so relabel it as an explicit fallback and move it last rather than leaving it in the JSON as-is. (hvac/plumbing's unfilled {{asked_by}}/{{practice_phone}} tokens were fixed in the home-services rewrite.)
- Routing additions (new choices) are fine when the task is explicitly a routing task: add the choice object to the JSON with the next sort_order and flows:apply inserts it; re-export afterwards to confirm the JSON round-trips. If a screen's coaching note names the URGENT button, that screen must have its own `urgent` choice.
- Making It Real screens share one scaled three-question shape (see style guide example 5). The owner's reference impact line ("...interfere with things like work, at home, or relaxing...") is 22 words and fails lint R2; the applied version drops "things like" (20 words). Keep every question ≤20 words with a single "?" — lint splits R1 units only on `.!`, so a question cannot be split in two.
- The facial-aesthetics JSONs were hand-written with compact one-line choices; any export (or JSON.stringify re-save) expands them, so a small text edit shows a ~800-line diff. Verify text-only changes by parsing HEAD vs working tree (choices/step meta identical), not by diff size.
- Task agents share the same Supabase flow tables, so an unmerged task's `flows:apply` can leave the DB ahead of main's JSON. Before `flows:apply --all`, read the dry-run and, for any step you did not touch that shows as an update, export that slug and adopt the DB text into the file rather than reverting it.
- Every flow routes Making It Real → `review` (general's review when the niche has none) → `recommendation`. The owner-approved read-back ("let me make sure I have this right… Did I get that right?") lives on `review`; `recommendation` opens with the bridge ("that's worth getting looked at instead of just dealing with it. Can I make a recommendation?"). Never put the read-back on both or the caller says it twice. The owner picked this split explicitly (Sept 2026). Two caveats: a niche with no `review` of its own inherits general's (work/home/own-time buckets), so any niche whose Making It Real buckets differ needs its own `review` override; and general's `doing_well_variant` "no signs" button goes straight to `recommendation`, so general's bridge must not presume an active problem (only matters when no niche is selected — the picker has no general option).
- `flows:apply --dry-run` on a niche can list steps you never touched: another merged task already wrote newer text into the DB that this branch's JSON does not have yet. Do not apply the whole file (it would revert that work). Recipe: copy your edited JSON aside, `flows:export <slug>`, splice the DB content for the untouched steps into your copy, apply, then restore your original edited file so the commit carries only your diff.
- Chip spoken phrases for parent-mode niches (Clear Aligners, Orthodontics) must be pronoun-free ("the shifting", "how the smile looks in photos"): mergeScript is single-pass, so a `{{pt_your}}` inside a spoken value would render raw, and "your" would misaddress the parent. Lint R15 enforces this, deriving parent mode from any `mode_parent*` step in the flow file (never a niche-name list); the shared chip table is a mutable object, so tests swap a niche's chips in place and restore them in `finally`.
- `flows:export` after apply also pulls in choice rows another unmerged task inserted (e.g. objection → scheduling buttons). For a text-only task, restore `choices` from git HEAD for those files instead of committing the other task's routing.
- Concurrent tasks re-apply the same niche from their own branch and can revert a choice label/sort_order you already applied (inserted rows survive). Re-run the dry run right before marking complete, and if a row regressed, export, patch only that row, apply, then restore your file.
- The player fetches the whole flow once per page load; after `flows:apply`, a click-tester must hard-reload before it sees new rows.
- Owner-approved rule: `{{provider_name}}` is always spoken as "Dr. <last name>" (never first name, never the business name — that sounds like a call centre); when no doctor applies it becomes "the whole office", so write the token mid-sentence in a shape that reads with either value.
- The API Server workflow is often stopped between sessions; a demo sign-in "Request failed (502)" in the player means restart it, not an app bug.

- Objection handles follow a five-beat shape (acknowledge, one isolating question, `(Let them answer.)`, niche reason tied to {{main_concern}}, unique low-stakes ask; see style guide under R9). Every niche uses it (chiro family first, the other 26 in Sept 2026), with same-key overrides for general's obj_cost/obj_time/obj_spouse/obj_other_option/uncover (uncover sort_order 12, overrides 120-123) so general.json stays generic. The owner confirmed, for chiropractic offices: front desk checks insurance before the visit; early/late openings; a returning patient's first visit is under 30 minutes.
- {{main_concern}} spoken values include noun phrases like "your reliance on those medications" and "getting back to the things you've given up", so write the token in "take a look at / what's going on with {{main_concern}}" shapes, never as the grammatical subject of "keeps coming back".

- Lint R12 (dead ends) decides "terminal" by step_key pattern only (`TERMINAL_STEP_PATTERNS` in scripts/flows/lib.ts). A new niche that ends a call on a step with a novel key (not scheduling/close_*/booked_wrap/*_bonus/voicemail/wrong_number/dnc/end*/wrap_up*) will lint as an error; either reuse a known key or extend the pattern list, do not allow-list it. When wiring obj_think/obj_send_info buttons, drop the niche from `KNOWN_DEAD_ENDS` (lint warns about stale entries).

**Why:** Text rewrites must never alter routing (no DDL, routing owned by the product); the tooling only updates text in place.
**How to apply:** Any script rewrite: flows:check → export → edit JSON → flows:lint → flows:apply --dry-run → apply → flows:check → click through in the player with the niche enabled for the demo owner.
- `flows:check` (DB vs content/flows drift, exit 1) is intentionally NOT a validation step: task branches share one live DB, so another task's applied-but-unmerged niche shows as DRIFT (expected mid-flight, e.g. lapsed_* screens). Read DRIFT on niches you did not touch as "someone else is in flight", not as your bug. Also: `flows:apply --dry-run` prints "0 updated" in its summary even when it listed changes; the counters only move on real writes.
- Five-beat objection rollout decisions: every niche (not only chiro) is on the lint's OBJECTION_SHAPE_NICHES list, so R9 violations are errors everywhere; non-chiro niches use the cash-pay cost shape and a "short window" time shape; chiro office facts (front desk checks coverage, early/late openings, sub-30-minute visit) stay chiro-only. A niche whose bridge_no still routes to general's obj_taken_care_of surfaces the legacy screen; point it at the niche's own equivalent instead. When rewriting a batch, generate the copy from one parameterized source (throwaway is fine) rather than hand-editing 26 files, and remember flows:apply never deletes a choice, so a repointed button must be removed from the DB by hand.
- The `{{main_concern}}` fallback renders as "what's been bothering you the most", so "what {{main_concern}} is already costing you" reads "what what's..." when no chip was tapped; avoid leading a token with "what" or keep the chip picked when click-testing.
- Before `flows:apply` on a batch, dry-run `--all` and adopt DB-ahead text on untouched steps (other tasks apply to the shared DB before merging); then apply only your slugs by name so other tasks' in-flight niches are untouched.

- Lint R16 (review buckets) reads the three impact buckets off the third Making It Real question ("interfere with A, B, or C?") and requires the effective review screen (own, else general's) to name each one, verbatim, by a declared short form (`IMPACT_BUCKET_EQUIVALENTS`), or by all content words. When a niche changes its buckets it must also carry its own `review` step; when a new short read-back form is wanted, declare it in the equivalents table rather than loosening the match. Rule numbers are hand-assigned in lint.ts and collided once (two R15s); check the header comment before picking the next number.
