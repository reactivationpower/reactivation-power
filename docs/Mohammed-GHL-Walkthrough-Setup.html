Send the full walkthrough to every new website inquiry

Goal: Every eligible person who submits their information receives the full product walkthrough, whether or not they choose an appointment. Unbooked prospects get a clear invitation to schedule. Booked prospects get preparation information, not repeated invitations to book.

This is a setup guide, not a claim that GHL has already been configured. Website integration behavior has been checked in the application code; the live GHL workflows have not been inspected or changed. Start by checking the existing welcome and booking workflows. Edit them where appropriate instead of creating duplicate email sequences. The new walkthrough page and video placement must be published before these email links are activated.

2. Check the existing GHL setup first

  1. Open the GHL location used by the Patient Pipeline website and find its existing lead/welcome workflows and strategy-call calendar. Confirm the exact calendar used by the website with the owner or technical team; do not substitute another calendar.
  2. The website creates or updates the GHL contact through the API and applies the existing tags healthcare-funnel and reactivation-power-lead. These are legacy technical names; keep them unchanged. Customer-facing emails should say Patient Pipeline.
  3. Use Contact Tag → Added → healthcare-funnel for new inquiry enrollment, filtered to this funnel. Do not rely on GHL's Form Submitted trigger: the website uses its own form, not a native GHL form. “Contact Created” alone also misses existing contacts.
  4. The website books appointments through the API with status Confirmed. Booking automation must use Appointment Status, filtered to the correct strategy-call calendar and Confirmed status. Include API-created appointments; do not restrict the trigger to customer/widget bookings. If other supported booking methods create New status first, cover that event too, with duplicate protection.
  5. Check that the current sender address/domain is authenticated, replies reach the right team, unsubscribe handling works, and email DND/opt-out is respected. Do not override suppression to force the walkthrough email.
Important: A tag trigger reacts to a new tag addition, not every submission by a contact who already has that tag. This guide sends the initial welcome once per contact. Existing tagged contacts do not automatically enroll when a workflow is published. Do not mass-enroll historical leads. If repeat submissions should restart the sequence later, that needs an explicit event and separate approval.

3. Workflow A — Thank you + walkthrough

Name: Patient Pipeline — Inquiry Welcome + Walkthrough

  1. Edit the existing funnel welcome workflow if it already serves this purpose; otherwise create this one. Use the Contact Tag trigger above. Disable repeat enrollment for this welcome.
  2. Check a new tracking tag, pp-walkthrough-welcome-sent. If present, end. Ensure no other workflow is sending a duplicate initial welcome.
  3. Send the thank-you email promptly, regardless of booking status. Use the universal copy below so a booking made while the email is queued does not make the message incorrect.
  4. After the email action completes successfully, add pp-walkthrough-welcome-sent. This means the send action completed, not that the email was delivered or the video watched. Check failed send actions separately.
  5. If the person is eligible for follow-up and has no active strategy-call booking, add them to Workflow C below. Workflow C must recheck booking status on entry.

Use GHL's merge-field picker to insert the first name and set a sensible fallback for missing names. Keep the existing appropriate business footer and unsubscribe link.

4. Workflow B — Booked: stop invitations and prepare for the call

Name: Patient Pipeline — Strategy Call Booked

  1. Modify the existing booking-confirmation workflow wherever possible. Use the Appointment Status trigger described above; enroll the primary contact only.
  2. Immediately add a new state tag, pp-strategy-call-booked, and remove the contact from Workflow C only. Do not remove them from Workflow A before their initial walkthrough email can be sent.
  3. Add the walkthrough link to the existing confirmation email. Keep the appointment's date, time, timezone, meeting/join details, and legitimate reschedule/cancel links. Do not create a second competing confirmation email.
  4. Use appointment-context merge fields from GHL's picker. The website also attempts to update {{contact.appointment_date_and_time}} after creating the appointment; that update can lag or fail, so do not treat the field as the booking signal or send blank/stale details. Test which fields resolve in the actual workflow.
  5. Include the walkthrough link in the existing pre-call reminder as an optional preparation step; preserve its appointment-relative timing. Do not require viewing to attend.
  6. Protect against duplicate confirmations for the same appointment if multiple triggers fire. Do not use a permanent “confirmation sent” tag that would block a later legitimate appointment or reschedule. Use the existing appointment workflow's repeat/enrollment behavior and verify it.

Suggested preparation copy for the confirmation email:

Before we meet, this four-minute walkthrough will show you how Patient Pipeline works.

Watch the full walkthrough

Bring your questions about how it would fit your office. During our call, we can show you the specific features or workflows you want to explore.

Cancellations and reschedules: Preserve existing calendar automations. Treat pp-strategy-call-booked as a derived state marker, not the permanent source of truth. A canceled appointment should not automatically restart this sales sequence. If updating the marker, check for another active appointment first; a cancellation during rescheduling must not trigger “you haven’t booked” emails. Completed or no-show appointments should not automatically receive fresh booking invitations from this sequence.

5. Workflow C — One follow-up for unbooked inquiries

Name: Patient Pipeline — Unbooked Walkthrough Follow-Up

  1. Enroll only from Workflow A after the initial welcome action. Disable repeat enrollment for this initial sequence.
  2. On entry, exit if the contact has an active strategy-call booking, the booked marker, a reply needing staff attention, email DND/unsubscribe, or the follow-up-sent tag.
  3. Wait 24 hours.
  4. Immediately before sending, repeat those checks. Configure stop-on-response for this follow-up workflow and verify replies are recognized by the connected mailbox.
  5. Send the single follow-up below, add pp-walkthrough-followup-sent after successful send, and end. Do not add more emails or SMS to this new sequence without approval.

Use the calendar's actual active appointment state where supported, plus the marker populated by Workflow B. Do not use an email open, link click, opportunity stage, or the appointment-date text field as proof of booking. If GHL's available conditions cannot check the correct calendar state, test the marker workflow carefully and flag that limitation before activating reminders.

6. Test before activating for real leads

Build in draft, then test with designated staff-owned addresses and phones. Tag triggers require an active workflow to fire; use a controlled test copy with an additional test-contact filter, or test actions manually before enabling the production trigger. Do not leave both test and production workflows sending to the same contacts. Do not bulk-message the existing database.

  • Publish the updated website first. Open the walkthrough link signed out on desktop and mobile; confirm video playback, sound, seeking, poster, and scheduling link.
  • Submit a brand-new test contact through the actual website and do not book. Confirm correct GHL tags, one initial welcome, correct walkthrough link, and one follow-up after the wait. A temporary shorter wait is acceptable in a test copy only.
  • Submit a test contact and book immediately through the website. Confirm the API-created Confirmed appointment triggers Workflow B, the welcome still arrives once, confirmation details are correct, and no unbooked reminder arrives.
  • Book after the initial welcome but before the 24-hour wait ends. Confirm pending unbooked follow-up is stopped.
  • Test an existing contact without the funnel tag, and a contact already carrying it. Verify expected one-time enrollment; never remove live customers' tags just to force testing.
  • Submit twice, reschedule, and cancel. Confirm no duplicate initial welcomes, duplicate confirmations, or inappropriate booking invitations. Also test an unrelated calendar appointment: it must not count as a Patient Pipeline strategy-call booking.
  • Test missing first name, a reply, email DND, and unsubscribe. Check suppression and merge-field behavior without overriding it.
  • Restore production wait times, remove test-only conditions from the intended production workflows, ensure old competing send actions are disabled, then activate the final workflows.

Return to the owner: Workflow names/links, trigger and calendar screenshots, email previews, test-contact results, and confirmation that duplicate sends and unbooked reminders are prevented after booking. Keep actual personal information out of shared screenshots.

7. Sales-team use

At the start of the call ask: “Did you get a chance to watch the walkthrough?” and “Are you mainly looking to bring past patients back, improve lead follow-up, or both?”

If they watched it, move straight to questions and targeted live demonstrations. If they did not, use the four-minute recording as the consistent baseline demo, then show the relevant functionality live. Receiving or clicking the email is not proof that someone watched the video.

Track initial-email sends, walkthrough-link clicks, and actual strategy-call bookings separately. Do not report link clicks as completed video views.
